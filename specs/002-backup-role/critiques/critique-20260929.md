# Critique Report: Backup Role for Infrahub Instances

**Date**: 2026-09-29 · **Artifacts**: spec.md, plan.md, research.md, contracts/role-interface.md · **Mode**: autonomous (fixes applied without approval, per `speckit-opsmill-prep`)

## Executive Summary

Right problem, right approach: wrapping the official `infrahub-backup` tool keeps the role thin and restore-compatible. Two gaps block implementation: the secrecy success criterion (SC-004) has no test that can actually observe Ansible's output, and scheduled-backup failures are silent. Several smaller robustness items. **Verdict: ⚠️ PROCEED WITH UPDATES** — all fixes applied below.

## Product Lens Findings 🎯

### Problem Validation

- Issue #163 asks for exactly this; scope (local + S3 + systemd, no restore/K8s) matches. No finding.

### User Value Assessment

- **P1 💡** Backup without a pointer to restore is half a DR story. → Docs page links the tool's restore guide and states restore is manual.

### Alternative Approaches

- Helm subchart covers K8s; cron considered and rejected (issue asks for systemd). No finding.

### Edge Cases & UX

- **P2 💡** Default `OnCalendar=daily` fires at 00:00; Community Edition stops the app during backup. → Default `*-*-* 02:00:00` (matches the tool's own cron example) and document the maintenance-window caveat.
- **P3 💡** `docker_project` default `infrahub` breaks hosts not installed by the `install` role with another project name. → Empty string omits `--project` so the tool auto-detects.

### Success Measurement

- **P4 🤔** Tool/Infrahub version compatibility (issue reporter on Infrahub 1.1.5) is owned by the tool. → Resolved: document that the pinned tool version's compatibility applies; operators override `backup_infrahub_version`.

## Engineering Lens Findings 🔬

### Architecture Soundness

- Flags-for-options / env-file-for-secrets split is sound. No finding.

### Failure Mode Analysis

- **E1 🎯** Scheduled backup failures (e.g. tasks running and `force: false`) only land in the journal; nothing tells the operator. → Add optional `backup_infrahub_on_failure` (systemd unit name for `OnFailure=`), and document `systemctl list-timers` / `journalctl -u infrahub-backup` checks.
- **E2 💡** Tool auto-detects DB credentials via `docker compose exec`; when that fails there is no way to pass `INFRAHUB_DB_PASSWORD` etc. → Add `backup_infrahub_environment` (dict, `no_log`) rendered into the 0600 env file; also an escape hatch for future tool options.

### Security & Privacy

- **E3 🎯** SC-004 ("no secret at any verbosity") cannot be verified from inside a playbook — a play can't capture its own stdout. Also `validate_argument_spec` and `template --diff` are the likely leak points. → Replace the in-playbook secrecy assertion with a wrapper script `tests/roles/backup/run.sh` that runs `test_render.yml` with `-vvv --diff`, captures output, and fails if the sentinel secret string appears. Env-file task keeps `no_log: true` + `diff: false`; argument spec marks both credentials `no_log: true`.
- **E4 💡** Values rendered into `ExecStart` containing `%` are interpreted as systemd specifiers. → Escape `%` → `%%` when rendering ExecStart; test with an S3 prefix containing `%`.

### Performance & Scalability

- N/A.

### Testing Strategy

- **E5 💡** Test playbooks are not wired into CI (CI edits are "ask first"). → Keep out of scope; list as follow-up in the implementation report.

### Operational Readiness

- **E6 💡** Role relies on `ansible_facts.architecture`; a play with `gather_facts: false` would fail with an undefined-variable error. → Gather `min` subset when the fact is missing.

### Dependencies & Integration

- **E7 💡** Pinned `v2.3.0` will age. → Document the variable prominently; follow-up: add the tool to the repo's dependency-bump automation (out of scope).
- **E8 💡** `--s3-upload` deletes the local archive by default, and S3 retention pruning needs `s3:DeleteObject`. → Document both on the docs page.

## Cross-Lens Insights 🔗

- **X1** E1 + P2: silent nightly failure at midnight during user hours is the worst combination; the 02:00 default plus `OnFailure=` addresses both.
