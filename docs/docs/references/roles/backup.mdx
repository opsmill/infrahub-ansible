The **Infrahub Backup Role** in the **OpsMill Infrahub Ansible Collection** installs the [infrahub-backup](https://github.com/opsmill/infrahub-backup) command-line tool and schedules backups of an Infrahub instance with a `systemd` timer. Backups are stored locally, uploaded to S3 or S3-compatible storage such as MinIO, or both, and can be encrypted.

# Overview

This role automates Infrahub backups by:

* Downloading the `infrahub-backup` binary from its GitHub release and verifying its checksum
* Creating the backup directory and a `0600` environment file for credentials
* Installing a `systemd` service and timer that run `infrahub-backup create` every day at 02:00
* Optionally running a backup immediately, for example before an upgrade

The role is a thin wrapper around `infrahub-backup create`. By default it passes only `--backup-dir` and `--retention-count 7`. Every other flag is passed only when its variable is set or `true`, so the tool's own defaults apply.

# Requirements

This role requires:

* A Linux host managed by `systemd`, on `x86_64` or `aarch64`
* An Infrahub instance deployed with Docker Engine and Docker Compose v2, for example with the [install role](./install.mdx). Kubernetes isn't supported yet (see [Not supported](#not-supported))
* Outbound HTTPS access to GitHub to download the tool, or an overridden `backup_infrahub_tool_url` (see [Air-gapped installs](#air-gapped-installs))
* Root or `sudo` access on the target host (`backup_infrahub_become` defaults to `true`)
* Host facts: the role gathers the minimal fact subset itself when `ansible_facts.architecture` is missing, so `gather_facts: false` works

The pinned tool version (`backup_infrahub_version`) sets which Infrahub versions are supported. Check the [infrahub-backup release notes](https://github.com/opsmill/infrahub-backup/releases) and override `backup_infrahub_version` when needed.

# Role variables

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `backup_infrahub_platform` | `str` | `docker` | Platform the Infrahub instance runs on. Only `docker` (Docker Compose) is supported for now. |
| `backup_infrahub_version` | `str` | `v2.3.0` | Release tag of `infrahub-backup` to install. Used to build the download URL. |
| `backup_infrahub_tool_url` | `str` | `https://github.com/opsmill/infrahub-backup/releases/download/{{ backup_infrahub_version }}/infrahub-backup-linux-{{ arch }}` | URL of the binary. `arch` is `amd64` or `arm64`. When you set it, also set `backup_infrahub_tool_checksum`. |
| `backup_infrahub_tool_checksum` | `str` | `sha256:https://github.com/opsmill/infrahub-backup/releases/download/{{ backup_infrahub_version }}/SHA256SUMS` | Checksum of the binary, as `<algo>:<hex or URL>`. Required when `backup_infrahub_tool_url` is set. |
| `backup_infrahub_install_tool` | `bool` | `true` | Whether to download and install the binary. Set to `false` when the binary is provisioned another way. |
| `backup_infrahub_bin_path` | `str` | `/usr/local/bin/infrahub-backup` | Path of the binary. Used as install destination and in the service `ExecStart`. |
| `backup_infrahub_backup_directory` | `str` | `/var/backups/infrahub` | Directory where backups are written (`--backup-dir`). Can be an NFS mount (see [Remote storage](#remote-storage)). |
| `backup_infrahub_backup_directory_mode` | `str` | `"0700"` | File mode of the backup directory. |
| `backup_infrahub_config_directory` | `str` | `/etc/infrahub-backup` | Directory holding the `infrahub-backup.env` environment file. |
| `backup_infrahub_docker_project` | `str` | tool default (auto-detect) | Docker Compose project name of the Infrahub instance (`--project`). Set it when several Infrahub projects run on one host. |
| `backup_infrahub_force` | `bool` | `false` | Pass `--force` to `create`. |
| `backup_infrahub_neo4j_metadata` | `str` | tool default (`all`) | Neo4j metadata to include (`--neo4jmetadata`). One of `all`, `none`, `users`, `roles`. |
| `backup_infrahub_exclude_taskmanager` | `bool` | `false` | Exclude the task manager database (`--exclude-taskmanager`). |
| `backup_infrahub_log_format` | `str` | tool default (`text`) | Log format of the tool (`--log-format`). One of `text`, `json`. |
| `backup_infrahub_retention_days` | `int` | unset | Keep backups newer than this many days (`--retention-days`). Must be at least 1. |
| `backup_infrahub_retention_count` | `int` | `7` | Keep this many most recent backups (`--retention-count`). Must be at least 1. `null` disables it and omits the flag. |
| `backup_infrahub_s3_upload` | `bool` | `false` | Upload backups to S3 (`--s3-upload`). Requires `backup_infrahub_s3_bucket`. |
| `backup_infrahub_s3_bucket` | `str` | unset | S3 bucket name (`--s3-bucket`). |
| `backup_infrahub_s3_prefix` | `str` | unset | S3 key prefix (`--s3-prefix`). |
| `backup_infrahub_s3_endpoint` | `str` | unset | Endpoint URL for S3-compatible storage (`--s3-endpoint`). |
| `backup_infrahub_s3_region` | `str` | unset (tool default `us-east-1`) | S3 region (`--s3-region`). |
| `backup_infrahub_s3_keep_local` | `bool` | `false` | Keep the local archive after uploading to S3 (`--s3-keep-local`). |
| `backup_infrahub_s3_access_key_id` | `str` | unset | S3 access key ID, written to the environment file as `AWS_ACCESS_KEY_ID`. Set together with the secret access key. Never logged. Must not contain a newline or carriage return. |
| `backup_infrahub_s3_secret_access_key` | `str` | unset | S3 secret access key, written to the environment file as `AWS_SECRET_ACCESS_KEY`. Set together with the access key ID. Never logged. Must not contain a newline or carriage return. |
| `backup_infrahub_encrypt` | `bool` | `false` | Encrypt backups with the built-in OpsMill public key (`--encrypt`). Only OpsMill can decrypt them (see [Encryption](#encryption)). Ignored when `backup_infrahub_encrypt_key` is set. |
| `backup_infrahub_encrypt_key` | `str` | unset | Absolute path on the host to a public key used to encrypt backups (`--encrypt-key`). Implies encryption. The role doesn't place the key file. |
| `backup_infrahub_setup_systemd` | `bool` | `true` | Whether to install the `systemd` service and timer. When `false`, the role installs no units and, if `backup_infrahub_systemd_manage_state` is `true` and a timer file exists, stops and disables that timer. Existing unit files are left in place. |
| `backup_infrahub_systemd_directory` | `str` | `/etc/systemd/system` | Where to install the `systemd` unit files. |
| `backup_infrahub_systemd_manage_state` | `bool` | `true` | Whether to reload `systemd` and manage the timer state. Set to `false` to only render the unit files. |
| `backup_infrahub_schedule` | `str` | `*-*-* 02:00:00` | `systemd` `OnCalendar` expression for the timer, in host time. |
| `backup_infrahub_randomized_delay` | `str` | `"0"` | `systemd` time span for the timer `RandomizedDelaySec`. |
| `backup_infrahub_service_user` | `str` | `root` | User running the backup service (`User=`) and on-demand backups. Needs access to Docker (see [Running as a non-root user](#running-as-a-non-root-user)). |
| `backup_infrahub_environment` | `dict` | `{}` | Extra environment variables for the tool, for example `INFRAHUB_DB_PASSWORD`. Written to the environment file. Never logged. Names must match `^[A-Za-z_][A-Za-z0-9_]*$`. Values must not contain a newline or carriage return. |
| `backup_infrahub_run_now` | `bool` | `false` | Run a backup immediately during the role execution, as `backup_infrahub_service_user`. |
| `backup_infrahub_become` | `bool` | `true` | Whether host-changing tasks use privilege escalation. |

The role writes these files on the target host:

| Path | Mode | Owner | Written when |
|------|------|-------|--------------|
| `backup_infrahub_bin_path` | `0755` | `root` | `backup_infrahub_install_tool` is `true` |
| `backup_infrahub_backup_directory` | `backup_infrahub_backup_directory_mode` | `backup_infrahub_service_user` | Always |
| `backup_infrahub_config_directory` | `0700` | `backup_infrahub_service_user` | Always |
| `backup_infrahub_config_directory/infrahub-backup.env` | `0600` | `backup_infrahub_service_user` | Always. Holds the S3 credentials and `backup_infrahub_environment`. |
| `backup_infrahub_systemd_directory/infrahub-backup.service` | `0644` | `root` | `backup_infrahub_setup_systemd` is `true` |
| `backup_infrahub_systemd_directory/infrahub-backup.timer` | `0644` | `root` | `backup_infrahub_setup_systemd` is `true` |

Owners are set only when `backup_infrahub_become` is `true`.

# Backup examples

<Tabs>
<TabItem value="quick-start" label="Quick start" default>

Install Infrahub and schedule a daily local backup at 02:00, keeping the last 14 archives:

```yaml title="backup_infrahub_minimal.yml"
- name: Install and back up Infrahub
  hosts: infrahub_servers
  become: true

  roles:
    - role: opsmill.infrahub.install
      vars:
        install_infrahub_version: "latest"
    - role: opsmill.infrahub.backup
      vars:
        backup_infrahub_retention_count: 14
```

</TabItem>
<TabItem value="remote-s3" label="Remote S3 or MinIO">

Upload every backup to an S3-compatible bucket. Keep the credentials in Ansible Vault:

```yaml title="backup_infrahub_s3.yml"
- name: Back up Infrahub to MinIO
  hosts: infrahub_servers
  become: true

  roles:
    - role: opsmill.infrahub.backup
      vars:
        backup_infrahub_s3_upload: true
        backup_infrahub_s3_bucket: infrahub-backups
        backup_infrahub_s3_prefix: prod/
        backup_infrahub_s3_endpoint: https://minio.example.com:9000
        backup_infrahub_s3_keep_local: true
        backup_infrahub_s3_access_key_id: "{{ vault_infrahub_backup_s3_access_key_id }}"
        backup_infrahub_s3_secret_access_key: "{{ vault_infrahub_backup_s3_secret_access_key }}"
        backup_infrahub_retention_days: 30
```

</TabItem>
<TabItem value="encrypted" label="Encrypted">

Encrypt every backup with your own public key. Place the key on the host first; the role only passes its path:

```yaml title="backup_infrahub_encrypted.yml"
- name: Back up Infrahub with encryption
  hosts: infrahub_servers
  become: true

  pre_tasks:
    - name: Place the backup public key
      ansible.builtin.copy:
        src: files/infrahub-backup.pub
        dest: /etc/infrahub-backup.pub
        mode: "0644"

  roles:
    - role: opsmill.infrahub.backup
      vars:
        backup_infrahub_encrypt_key: /etc/infrahub-backup.pub
```

</TabItem>
<TabItem value="pre-upgrade" label="Pre-upgrade backup">

Take a single backup right now, for example before upgrading Infrahub. Only `backup_infrahub_run_now` is set, so the scheduled timer is installed or kept as is:

```yaml title="backup_infrahub_now.yml"
- name: Back up Infrahub before an upgrade
  hosts: infrahub_servers
  become: true

  roles:
    - role: opsmill.infrahub.backup
      vars:
        backup_infrahub_run_now: true
```

The on-demand backup runs as `backup_infrahub_service_user`, like the scheduled one, with the same flags. A `/bin/sh` wrapper sources the same environment file the scheduled service reads, then starts the tool. Credentials never appear on a command line, so they don't show up in `ps`, and they never appear in Ansible output. When the tool fails, the role fails with the tool's error message.

To remove the schedule, set `backup_infrahub_setup_systemd: false`. The role then installs no units and, when `backup_infrahub_systemd_manage_state` is `true` and a timer file exists, stops and disables the timer. The unit files are left in place.

</TabItem>
</Tabs>

Run the playbook with:

```bash
ansible-playbook backup_infrahub.yml -i inventory.yml
```

# Checking scheduled backups

List the timer and its next run:

```bash
systemctl list-timers infrahub-backup.timer
```

Read the output of past runs:

```bash
journalctl -u infrahub-backup.service
```

Start a backup outside the schedule with `systemctl start infrahub-backup.service`.

# Community Edition and Enterprise backups

* **Community Edition is backed up offline.** The tool stops the Infrahub services while it dumps the databases, then restarts them. Schedule backups in a maintenance window with `backup_infrahub_schedule`. The default is every day at 02:00, host time.
* **Enterprise is backed up online**, with no downtime.

A backup restores only to the edition that produced it.

# Retention

The role keeps the 7 most recent backups by default (`backup_infrahub_retention_count: 7`). Set `backup_infrahub_retention_count: null` to disable it; with `backup_infrahub_retention_days` also unset, the tool never deletes a backup.

* **The rules combine as a union.** With both `backup_infrahub_retention_days` and `backup_infrahub_retention_count`, the tool keeps every backup newer than the age limit *and* the most recent backups up to the count, whichever set is larger. For a hard cap on the number of archives, set only `backup_infrahub_retention_count`.
* **The newest backup is always kept**, at each location.
* **Retention runs after a successful backup.** A failed backup never deletes anything.
* **The local directory and the S3 prefix are pruned separately.** Pruning on S3 needs `s3:ListBucket` and `s3:DeleteObject` on the bucket.

See the [infrahub-backup retention guide](https://docs.infrahub.app/backup/backup/retention) for the full semantics.

# Encryption

The tool can encrypt each archive (`….tar.gz.enc`). Choose one mode:

* **Your own public key**: set `backup_infrahub_encrypt_key` to the absolute path of a public key on the host. You place the key file on the host, for example with `ansible.builtin.copy` before the role runs; the role only checks that the path is absolute. You decrypt the archives with the matching private key.
* **The built-in OpsMill key**: set `backup_infrahub_encrypt: true`.

:::warning

Archives encrypted with the built-in key can only be decrypted by OpsMill. You can't restore them yourself. Use `backup_infrahub_encrypt_key` if you need to restore without OpsMill.

:::

When `backup_infrahub_encrypt_key` is set, `backup_infrahub_encrypt` is ignored.

# Remote storage

* **S3 and S3-compatible storage** are supported natively by the tool. `--s3-upload` removes the local archive after a successful upload; set `backup_infrahub_s3_keep_local: true` to keep a local copy.
* **NFS or other network filesystems**: mount the share on the host yourself and point `backup_infrahub_backup_directory` at the mount point. Retention then applies to the share.

# Running as a non-root user

By default the backup runs as `root`. To use another account, set `backup_infrahub_service_user`. The role doesn't create the user. That user must:

* Belong to the `docker` group, or otherwise have access to the Docker daemon
* Own the backup directory and the config directory with its environment file. The role sets this ownership when `backup_infrahub_become` is `true`

# Multiple Infrahub projects on one host

The tool auto-detects the Docker Compose project of the Infrahub instance. When several Infrahub projects run on the same host, set `backup_infrahub_docker_project` to the one to back up.

# Credentials

The S3 credentials and `backup_infrahub_environment` are written to the `0600` environment file as `KEY="value"`, with `\`, `"`, `$` and `` ` `` escaped. The scheduled service reads it through `EnvironmentFile=`, and on-demand runs source it with `/bin/sh`. Both read back exactly the value you set, so any character works except a newline or carriage return, which the role rejects. The values never appear on a command line or in Ansible output.

# Not supported

The role deliberately doesn't expose these tool features:

* **Redacted backups.** The tool's `--redact` option replaces every attribute value in the **live** database with random data before the backup is taken. It's irreversible, so the role never passes it. To produce a redacted backup for sharing:
  1. Take a normal backup with this role.
  2. Restore it to a throwaway Infrahub instance.
  3. On that throwaway instance, run `infrahub-backup create --redact --force`.
  4. Share the resulting archive, then delete the throwaway instance.
* **`--sleep`.** Only useful for copying files out by hand during an interactive run.
* **The Plakar backend** (`--backend`, `--repo`).
* **Restore.** Restoring is a manual operation with the `infrahub-backup` tool. Follow the [infrahub-backup restore guide](https://docs.infrahub.app/backup/backup/restore).
* **Kubernetes.** Only Docker Compose deployments are supported. Kubernetes support is planned.

# Air-gapped installs

Without access to GitHub, host the binary and its checksum on an internal server and override both `backup_infrahub_tool_url` and `backup_infrahub_tool_checksum`. The role fails when only the URL is set:

```yaml
backup_infrahub_tool_url: https://artifacts.example.com/infrahub-backup/v2.3.0/infrahub-backup-linux-amd64
backup_infrahub_tool_checksum: sha256:https://artifacts.example.com/infrahub-backup/v2.3.0/SHA256SUMS
```

`backup_infrahub_tool_checksum` also accepts a literal hash, for example `sha256:<hex>`. Alternatively, provision the binary another way and set `backup_infrahub_install_tool: false`.
